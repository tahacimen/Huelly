# Huely

Hyper-casual color sequence matching game. Single-file HTML/CSS/JS game, wrapped
as an Android app with Capacitor.

## Run locally

Open `www/index.html` in a browser, or serve it:

```bash
npx serve www
```

## Structure

- `www/index.html` — the entire game (styles, markup, and logic in one file)
- `android/` — native Android project generated by Capacitor
- `capacitor.config.json` — app id (`com.tahacimen.huely`), name, and `webDir`

## Android build

After changing anything in `www/`, copy the assets into the native project:

```bash
npx cap sync android
```

Then build from Android Studio (`npx cap open android`), or from the CLI:

```bash
cd android
./gradlew assembleDebug     # -> app/build/outputs/apk/debug/app-debug.apk
```

The CLI build needs `JAVA_HOME` set to Android Studio's bundled JDK
(`C:\Program Files\Android\Android Studio\jbr` on this machine).

> **Gotcha:** if `TMP`/`TEMP` points at an 8.3 short path (e.g.
> `C:\Users\TAHA~1.CIM\AppData\Local\Temp`), Gradle dies with
> `Unable to establish loopback connection` — Java cannot bind its AF_UNIX
> socket there. Point `TMP`/`TEMP` at a normal path (e.g. `C:\Temp`) and it
> builds fine. Android Studio is unaffected; it uses the full path.

## Tech notes

- **Storage** is layered so progress survives everywhere: `window.storage` (Claude
  Artifacts) → `localStorage` (real browsers + Android WebView) → in-memory fallback.
  A published build persists via `localStorage`.
- **Global leaderboard** runs on Supabase (project `Huely`, region `eu-central-1`),
  called directly over the REST API — no SDK, so the single-file build stays intact.
  All writes go through the `submit_score()` RPC (`SECURITY DEFINER`), which only ever
  raises a player's score, so a tampered client cannot lower anyone. The publishable
  key shipped in the client is safe by design; row-level security blocks direct writes.
  Offline play still saves locally and syncs on the next save.
- The game itself has no runtime dependencies; Capacitor is only the native shell.
